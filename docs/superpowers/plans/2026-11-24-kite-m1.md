# Kite M1 实施计划：协议、服务端骨架、E2EE 配对与消息

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:execating-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付第一个端到端可用的增量：两个客户端经公网服务端完成注册、发现、异步配对（X3DH 密钥交换）并进行 E2EE 文本消息收发（双棘轮），离线消息可靠补投。

**Architecture:** Rust workspace：`kite-core`（平台无关：协议、加密、本地存储）、`kite-server`（axum + SQLite：注册/目录/信箱/配对信令）。客户端通过 TLS REST + WebSocket 与服务端通信；加密采用 Signal 式 X3DH + Double Ratchet，服务端只接触密文信封。

**Tech Stack:** Rust 1.99, axum 0.8, tokio, rusqlite, tokio-tungstenite, ed25519-dalek 3, x25519-dalek 3, chacha20poly1305, hkdf, sha2, serde/serde_json, reqwest, tracing

**Spec:** `reference/tech-design.md`（§2 安全设计、§3 架构、§4 数据模型、§6 传输协议要点）

## Global Constraints
- 服务器只见密文：任何 API 的 payload 必须是密文信封 `{type,to,sender,ciphertext,seq,ts}`，服务端不解密、不存储明文
- 所有客户端↔服务端流量走 TLS 1.3（开发期允许 rcgen 自签证书 + 客户端锁定指纹；生产 Let's Encrypt）
- `device_id = SHA-256(Ed25519 身份公钥) 前 16 字节 hex`，注册后不可变
- 设备名可重名（主键 device_id）；硬件指纹仅 argon2 加盐哈希存档
- 未 ACK 的信箱条目持久保存，不受配额限制（配额淘汰逻辑属 M2，本计划不实现）
- 密码学不自造：X3DH/双棘轮基于 dalek 系列原语按 Signal 规范组合；全部密码学代码必须有已知答案测试（KAT）
- 每个任务完成即 commit；测试全部通过才能 commit

## Review Focus
- 重放攻击：同一 X3DH 初始握手包重放给服务端/客户端应被拒绝（OPK 单次使用 + ts/nonce 窗口校验）→ Task 5 测试
- ACK 语义：客户端收到消息但未 ACK 时服务端崩溃重启，消息必须仍在 → Task 6 测试（kill -9 后重启断言信箱条目仍在）
- 游标语义：`since` 游标必须单调、无空洞无重复投递 → Task 6 测试（断线重连拉取不丢不重）
- 未注册/离线设备：发往不存在 device_id 的消息必须 404 且不落盘；发往离线设备必须落盘等待 → Task 6 测试
- 时间戳偏差：信封 ts 偏差超过 ±120s 应拒收（防重放窗口）→ Task 5 测试

**Interfaces:**

  - `GET /sync?since=N&wait=1`（带 token）→ `[{seq, from, kind, payload, ts}]`；wait=1 时 long-poll 至多 25s（tokio::sync::Notify 每 owner 一枚，enqueue 唤醒）；返回即视为已投递，**未 ACK 前不删除**

  - `POST /pair/respond` body `{to, accept: bool, payload(b64)}` → kind="pair_resp"
  - 表 `mailboxes(id INTEGER PRIMARY KEY AUTOINCREMENT, owner_id TEXT NOT NULL, seq INTEGER NOT NULL, from_id TEXT NOT NULL, kind TEXT NOT NULL, payload BLOB NOT NULL, ts INTEGER NOT NULL, UNIQUE(owner_id, seq))`；seq 在事务内 `COALESCE(MAX(seq),0)+1`
- 语义锁定（Review Focus 对应）:
  - ACK 前服务端重启条目必须仍在（WAL 模式 + 无内存缓存）
  - since 游标增量拉取不丢不重（seq 严格递增）
  - 离线设备条目落盘等待
